# AI 法庭：电子斗蛐蛐 V1.2 行动预览与三模式整合版

本次整合服务器动态预览、三种模式、最终确认和真实结算。健康接口使用 `version: 2.0.0`、`experience: 1.2`；实际计分仍为回合引擎 v2。改动、信息边界和验收见 [V1.2 更新说明](docs/V1.2-UPDATE.md)。旧文档保留为历史资料。

房主创建时选择休闲／标准／硬核模式，准备阶段可更换（双方需重新准备），开庭后锁定。三种模式共用全部行动、成功率、资源及判决规则，只改变出招前的信息量。休闲显示可确定数值及条件范围；标准只显示方向、条件、风险和代价；硬核仅显示用途、目标、必要条件及消耗，服务器不返回预测字段。所有模式结算后都显示真实结果。

选择目标或战术后会请求不调用模型的私有预览。点击“查看确认摘要”后，可“返回修改”或“确认出招”；只有最终确认才提交行动。依赖隐藏证明力或关联的数值使用**公开可能性的保守范围**，不预报隐藏答案；可确定的效果考虑当前上下限和防火墙。选项切换、预览及打开摘要均不扣资源、不掷真实骰、不消耗模型预算。

玩家决定行动，AI 负责表达，程序负责裁决。两名游客通过房间码会合，分别配置自己的模型和装备。开局后辩方先手，玩家选择行动、目标和战术，点击“确认出招”才生成一次发言。结算后等待另一名玩家，三轮交锋及双方最终陈词共八次行动。

旧版全自动连续辩论已替换。免费预设表达器也必须逐回合确认；它不调用外部模型。游戏使用 React、TypeScript、Vite、Express、Socket.IO，以及可选的 MySQL 8 / Prisma。

## 案件与庭审体验

钻石案为虚拟游戏道具转移案，检查未发现与披萨案、机器人案混用。开局绑定同一份不可变案件快照及版本；显示、AI 和结算都使用它，版本异常会安全中止。三案新增争议点，21 份材料分别说明“发生了什么／能说明什么／不能说明什么”，原始记录可展开。双方可见、正式出示、曾被质疑、已复核分别标记；公开不等于已经出示，已出示不能重复。

律师只表达本次选定的行动；正文引用材料名称，法庭另行宣布程序结算理由。默认选项、证据预览和展开面板均不调用模型。庭审采用屏内工作区，实录、证据与行动选项分别滚动；选择行动后收起选项，确认区始终保留。

庭审、实录和行动面板统一判定状态，结束／中止优先，不再被清除密钥误判为等待重连。界面中的“AI 冷静值”沿用原 stability 数值规则；普通行动最多五个入口，最终陈词保留四种选择。向上阅读历史时，新发言只增加提示；回到最新才继续跟随。

## 启动

需要 Node.js 22.12 以上或 Node.js 24 LTS。桌面完整包含 Windows 已安装依赖和构建产物，可双击 **启动游戏.cmd**。启动器在本机选择空闲端口并打印可打开的网址；保留窗口以运行服务器。

从源码安装：

```powershell
npm ci
Copy-Item .env.example .env
npm run db:generate
npm run build
npm run play
```

默认内存模式无需数据库。开发运行 `npm run dev`，访问 `http://localhost:5173`。构建后也可运行 `npm start`，默认 `http://localhost:3001`；如端口被旧服务占用，使用 `npm run play` 自动选择空闲端口。健康接口 `/api/health` 返回 `version: "2.0.0"`、`rulesVersion: 2`、`gameplay: "player_command"`。

免费预设可通过 HTTP 试玩。真实 API 配置和测试必须使用 HTTPS/WSS：

```powershell
npm run dev:https
```

访问 `https://localhost:5173`。首次生成的本机自签名证书需要你自行核实和信任；生成的证书与私钥不会打入交付包。公网部署使用实际域名的可信证书，详见 [部署说明](docs/DEPLOYMENT.md)。

开发服务已禁止浏览器读取后端源码、测试、数据库资料、文档、运行目录和证书。不要移除 `vite.config.ts` 中的文件访问限制；生产环境只发布构建后的前端文件，通过后端接口取得授权数据。

## 两人完成一局

1. A 填昵称、选择案件并创建房间；A 担任辩方。B 在独立页面输入房间码加入，担任控方。房间最多两人。
2. 双方保存 AI 配置。首次测试选“预设台词 · 免费试玩”，无需 Key。也可各自选择国内服务商、填写模型 ID 和自己的密钥。
3. 选择身份与最多三件道具，点击“保存装备，返回房间”。模型和装备独立保存，偏好自动记忆，密钥不保存在浏览器。
4. 双方点“我已准备”，房主点“开始对局”。此时行动计数应停在 **0/8**，不会自行调用模型。
5. 辩方点击行动卡片，选择证据或公开论点、战术风格，查看最新预览，点“查看确认摘要”；可返回修改，最后点“确认出招”。所选私证会显示公开提示。
6. AI 只表达这一条指令；服务器结算并交给控方。控方看到不同的行动菜单，选择反击。等待期间可以查看证据和实录。
7. 三轮后，双方分别选择并确认最终陈词。逻辑总结、集中反驳、强势陈词和冒险陈词各有固定条件及有限分值。
8. 第八次行动保存后，程序按最终证据强度和案件阈值判决。报告显示评分曲线、战术、随机判定、稳定度、资源、模型请求及费用估算。

道具占一次正式行动，不增加回合或模型调用。点“选择本回合行动 ↓”可跳到操作区。具体数值见 [回合规则](docs/RULES.md)。

同机使用从地址栏新开的两个标签页或独立浏览器会话；不要复制带有游客重连凭据的旧标签。游客与配置会话凭据保存在各标签的 sessionStorage，关闭标签可能失去原席位的重连资格及密钥自动恢复能力。刷新会从仍在运行的服务器恢复真实进度和已记住的模型连接，不会自动提交草稿。已接受的行动有界结算一次，下一回合等待恢复。

保存一次 AI 配置后，同一标签页退出旧房间、创建或加入新房间时，会自动提交上次保存的服务商、模型、风格、已保存装备及服务器暂存的 Key。进入新房间后仍需手动准备，不会测试连接或自动调用模型。独立新标签不继承这份密钥；模型和装备的非敏感偏好继续沿用原有本地记忆。配置页的“自动沿用与密钥使用说明”里可点击“清除自动沿用”；清除不影响当前房间的已提交配置，再次保存会重新记住。

朋友不能用自己电脑上的 localhost 访问你的服务器。两台设备必须访问同一部署地址，按部署文档配置监听地址、HTTPS 和允许来源。

## 服务商、费用与密钥

保留 19 家国内服务商预设；模型 ID 可手动填写。相同服务商/相同模型、同平台不同模型和跨平台对局均使用各自配置。厂商鉴权及兼容限制见 [服务商说明](docs/PROVIDERS.md)。Base URL 仅接受对应服务商已核实的官方 HTTPS 端点，DNS 地址经过公私网检查并固定，不跟随重定向。

密钥仅由本人的 HTTPS 私有连接提交，不进入 MySQL、公开广播、普通日志或浏览器存储。断线、结束、取消及清理仍删除活跃房间中的 Key；为了跨房间自动沿用，独立配置会话还在服务器内存保留一份副本。连续 12 小时未使用、手动清除或服务关闭时删除；服务器重启后需重新填写。服务端已接受的请求可持有该次调用的临时副本，直到有界调用结束。

配置会话以服务器生成的 256 位随机凭据授权，仅通过私有 Socket.IO 回执交给当前标签页，保存在 sessionStorage（其中没有 API Key）。服务器最多保留 1000 份临时配置，定期清理；恢复真实 Key 同样要求 HTTPS/WSS。未知/过期凭据及未携带凭据的新标签都不能读取或继承密钥。旧版本已清除的 Key 无法找回，升级后需要首次保存一次。

每人四次主要行动。真实请求最多八次主要调用，单次最多重试一次、全局最多两次重试，外部尝试总数最多十次。单次输出上限 320 Token，默认超时 12 秒。判决不调用 LLM。连接测试是玩家主动发起的额外请求，会计入每日预算。

超时、无效 JSON、模型擅自改动作、额度/预算或频率限制均降级为**同一已确认指令**的预设台词，不重新选招、不重新掷骰、不因技术故障扣稳定度。费用缺少可靠用量或单价时显示未知；有单价时仍只是估算，以服务商账单为准。

每日调用及保守预算预留沿用 `.env.example` 的 `DAILY_CALL_LIMIT`、`DAILY_BUDGET`、`UNKNOWN_CALL_RESERVE`。运行时预算文件只保存日期、请求数和数值预留，不包含密钥；不要删除它绕过限制。

## 规则实现与历史兼容

- `server/app.ts`：权威回合控制、幂等回执、一次行动执行、连接及密钥隔离。仅 `game:submit_action` 启动游戏模型调用；开局、重连和补密钥均不出招。
- `server/game.ts`：动态菜单、输入验证、冻结规则效果及随机结果、最终提交与新规则回放。`server/legacy-game.ts` 和 `server/legacy-turn-game.ts` 仅保留旧记录的只读规则回放，没有选招器、调度器或 Socket 入口。
- `server/llm.ts`：沿用 Provider Adapter 和费用保护，提示词只接收公开材料、本次选中材料与最近四次公开发言。输出必须匹配已锁定指令。
- `shared/types.ts`：行动命令、菜单、回执、执行状态、战术及随机记录协议。
- 前端行动面板和庭审/报告沿用首页的深灰、蓝色和琥珀色；首页、房间和 API 配置功能保留。窄屏通过庭审、证据和状态标签切换。

无需数据库结构迁移。新案件快照写入 `engineVersion: 2`、`experienceVersion: 2`、`matchMode`；案件内容版本仍为 4，固定事实和计分未改变。事件 JSON 保存 actionId、actorId、turnId、目标、战术、随机值、发言、结算和时间。复盘必须使用本局快照，不能拿当前目录模板代替。旧版快照仍按原规则回放；缺少快照的旧数据保留原始事件和结果。

## 可选 MySQL

默认 `STORAGE_MODE=memory` 不保存长期战绩。要保存，使用专用 MySQL 8 数据库，配置服务端 `.env` 中的 `DATABASE_URL` 和 `STORAGE_MODE=mysql`，然后：

```powershell
npm run db:generate
npm run db:migrate
npm run db:seed
npm run play
```

种子与服务初始化会中止数据库中遗留的未完成对局，不能在同一数据库上同时运行多个服务进程。服务端重启无法恢复进行中房间，会标记中止并清除判决；不会静默补打一局。已结束历史数据保留。数据库没有 API Key 字段，也没有客户端读取完整模板的接口。当前没有大厅历史查询页面。
