# 暗色剧场与幕后包厢

窗口以深墨蓝 `#151923` 为底，私密面板为 `#222938`，主要文字 `#E9EDF3`，次要文字 `#B1BAC8`。雾蓝 `#91B7CF` 标记己方关系，旧金 `#D3A284` 标记舞台重点与主要操作。

对局画面只提供全屏 3D 第一视角：程序化简模房间、椭圆桌、对席代理人与桌面物件。顶部悬浮 HUD 显示品牌、议题、三幕与阶段，底部固定字幕和自动演出门闩。公开谈判桌与完整实录收进左下“桌面档案”抽屉；右侧仍是自家代理人的幕后包厢，改为抽屉呈现。

右侧包厢包含身份、信任、本幕方针、私密汇报、隐藏副目标、方针卡与公开卡输入。信任使用数值与文字描述，变化原因展开查看；不使用血条或受击效果。汇报正文直接显示并说明代理人如何理解本幕方针，旧汇报折叠。

“你的隐藏副目标”卡片固定在汇报滚动区顶部：标题、说明与“达成 +5 心理分”同屏可见，不占新抽屉、不进入全屏 3D、公开事件或顶栏。对局中不显示达成状态，也不显示对方副目标。赛后复盘新增“隐藏副目标”区块，双方各一行展示标题、达成/未达成（达成时附心理分 +5）与判定依据；判定依据只来自公开事件、承诺账本与最终协议。

私密阶段显示守价、试探、施压、成交四张方针卡，公开阶段显示承诺、施压、表态三张公开卡；两者各有可选备注并分别保存草稿。卡片选中后会显示完整说明；只有对应阶段可以发送，已提交的模式不可再次提交。

对局舞台适配 1440×900 与 1280×720，字幕和门闩按钮固定在视口内，不需要页面滚动。窗口宽度小于 900px、WebGL 不可用或 3D 加载失败时只显示“3D 舞台不可用”提示，不渲染 2D 舞台。准备页与赛后复盘页仍使用原有舞台素材。

标题优先使用思源宋体，回退至中文宋体；正文优先使用微软雅黑及系统中文无衬线字体。正文 16px、辅助信息至少 14px，提供舒适阅读放大选项。所有主要操作支持键盘焦点，原生弹窗负责焦点约束与关闭后返回。

新汇报使用一次短暂边缘提示，耳语送达反馈约 220ms。系统或窗口设置启用减少动态效果时，关闭动画和过渡。

公开交锋默认由本机中文语音按正常人类语速朗读：服务端优先调用 Windows 已安装的中文语音，浏览器语音作兜底；可用全屏顶栏或“窗口设置 · 代理人语音”关闭。关闭或系统缺少中文语音时，仍按正常阅读语速推进，不会一句一闪而过。两倍速同时作用于动作与朗读。

底部门闩条：自动演出就绪约 800ms 后客户端自动确认，按钮仍显示“开始本回合交锋”“继续下一步”“进入公开低语”“进入下一幕”或“查看赛后结果”；暂停或抽屉打开时停在门闩并显示“继续”。按钮就绪时用旧金边强调；等待对方时显示等待状态。“暂停演出”“恢复演出”与“跳过演出”位于加速开关旁，正文说明当前是自动演出还是已暂停。

窗口设置现包含“代理人语音”与“环境音”，与顶栏开关共用同一份偏好并保存在本机 `localStorage`。

## 3D 全屏沉浸与悬浮 HUD

对局舞台只有全屏 3D：`position: fixed; inset: 0` 的 3D 画布铺满视口，页面不再出现外层滚动条。顶栏为半透明顶部渐变，底部叠加暗角以保证字幕可读；没有分栏 3D、经典 2D 或布局切换。

顶栏包含品牌、议题、房间码、三幕进度、当前阶段/倒计时、连接状态、语音开关、设置与离开。底部固定发言字幕条与自动演出门闩，1280×720 时仍无需滚动即可查看演出或点击“继续”。顶部与底部 HUD 通过 `pointer-events` 隔离：点击 HUD 不触发相机拖动，只有画布区域允许小幅转头。

右下“幕后包厢”为抽屉：包含身份、信任、本幕方针、本轮汇报和方针卡/公开卡。私密或公开耳语阶段且尚未提交时自动打开，提交后自动收起；可手动关闭、点击遮罩或按 Esc 关闭，Tab 焦点约束在抽屉内。抽屉打开期间自动演出暂停，关闭后恢复。遮罩底边停在上方，不遮挡底部门闩。左下“桌面档案”抽屉复用谈判桌、时间线与文字实录组件，提供完整报价、协议、声明、凭证、公开承诺与议题资料。

桌面宽度不小于 900px 且支持 WebGL 时进入 3D 舞台；窗口过窄、WebGL 不可用或 3D 模块加载失败时，只显示“3D 舞台不可用”提示，提供窗口设置与离开入口，不渲染 2D 舞台，也不提供布局切换。

全屏相机取景：对手位于画面中上部，桌面在下部，己方手臂在手边底缘；16:9 垂直 FOV 约 50°，21:9 约 47°。相机只允许小幅拖动，不自由行走。`prefers-reduced-motion` 或“减少动态效果”会关闭呼吸、镜头漂移、尘埃旋转和抽屉转场。3D 只使用公开事件与桌面重建结果，不显示底线、方针、备注、耳语或私密汇报。

## 场景与声音

场景按公开的 `room.scenario.id` 切换，不读取私密字段：

- 《最后一块电池》：暴雨窗光、应急灯、电池箱、积水反光；冷蓝与应急橙。
- 《封港前的船票》：港口雾、船钟、潮汐钟、货箱；雾灰与钠灯暖黄。
- 《静默档案》：档案架、台灯、封存袋、灰尘；档案暖黄与冷阴影。

三幕使用三档灯光与曝光：第 1 幕冷、远、阴影长；第 2 幕暖、近、顶光收紧；第 3 幕对比最强、对手灯更亮、己方侧稍暗，雨势、潮汐或档案灯随之加强。幕间用约 1～1.5 秒的过渡，减少动态效果时直接切换。

对手只对公开 `ActionUnit` 反应：有效质疑前倾、质疑未成立后仰、查验靠近桌面、成交点头、违约收手、暂缓靠回椅背；另有轻微呼吸与眨眼，减少动态效果时关闭。场景不提供“说谎必露馅”的暗提示。

环境音只播放本机 Web Audio 程序化生成的短事件音效：纸张、筹码落下、翻页、质疑、封蜡、盖章、幕间短音与违约裂响。不启动循环噪声音床、雨声、电流声或持续低频轰鸣；朗读时自动压低音效，顶栏与窗口设置仍可关闭，偏好保存在本机。音效不请求外部服务，也不引入音频文件。

结束仪式只使用公开结果：成交时合同纸滑到桌中央、金色封蜡落下、双方名牌变亮；未成交时文件收拢、灯光逐盏熄灭。减少动态效果时直接呈现最终状态，不显示秘密、私语或分数明细。

桌面交易是 3D 画面的主角。桌面中部偏上常驻一只筹码盘，固定摆 12 枚筹码；这 12 枚是公开的“报价刻度”，不是任何一方的预算或余额，标签写“桌面筹码”。当前报价或协议为 N 枚时，N 枚筹码移到桌面中央的报价位，排成 1～3 摞，剩余筹码留在盘内；报价位旁的纸签写“报价 N 枚”或“协议 N 枚”，协议形成后筹码转为旧金色。另一侧是浅色小托盘，电池、货位或档案盒比旧版缩小约一半，标签分别写“备用电池”“货位”“档案盒”，不再使用“标的物”术语。报价时由该方交易手（前臂、手掌与四指，肤色与袖口按席位区分）把筹码摆上桌；换价时旧筹码先由上一报价方收回盘内，新报价方再摆入；成交时筹码推向卖方、物件交给买方，合同纸与金色封蜡落下；中途协议仅显示“待执行”封签，物件不移动。筹码与物件只读取公开 `table.offer / table.agreement`，不读取底线、预算或私密提议。

筹码盘、物件托盘与手部动作位于桌面中部偏上，避开底部字幕条和门闩；报价卡、协议卡、声明卡移到桌面两侧的上方，不压住交易物件。1440×900、1920×1080 与 1280×720 都能同时看到筹码盘、物件和当前报价标签。`.stage-3d` 公开 `data-chips="12"`、`data-lot`、`data-offer`、`data-agreement`、`data-trade`（idle / place / withdraw / handoff / return），全部来自公开状态。

## 桌面档案与演出增补

公开物件不再占据主画面，完整报价、协议、声明、凭证、承诺、时间线与文字实录集中在左下“桌面档案”抽屉。抽屉内物件独立滚动，当前行动客观结果固定可见。报价与协议用雾蓝/旧金区分，状态同时用文字表达；未验证声明保持中性。

报价推出、凭证翻开、证据连接与协议合并只由结构化执行事件触发。旧报价进入历史，已有协议独立保留。价格承诺以封签绑定报价，确认违约时对照原承诺和新行动；3D 低模角色以手臂姿态服务于物件变化，普通物件约 550ms，关键变化约 850ms。底部 HUD 支持两倍速度、暂停/恢复与跳过；跳过只展开当前这一步，未暂停时随后自动确认。

回看提供实时阶段提示和返回入口，不会触发下一步；返回实时后继续自动演出。完整设计与事件说明见 [交锋过程可视化](NEGOTIATION-VISUALIZATION.md)。
