# V1.2：行动预览与三种模式

2026-10-29；基于 V1.1 工作副本整合，无新增依赖、无数据库迁移。

## 检查发现与实际补充

原有：玩家手动回合、合法菜单、私证隔离、规则引擎、行动幂等锁、模型有限重试与费用保护、19 家服务商、配置沿用、三案／三身份／六道具、旧记录严格复盘。

原有静态说明不等于 V1.2 预览。本次补充私有动态预览接口、三模式服务器投影、模式锁定、最终确认弹窗、局势摘要、完整真实结算与预览差异解释。没有重建房间、模型或评分系统。

## 三模式接入

| 模式 | 最终确认前服务器提供的信息 |
| --- | --- |
| 休闲 casual | 用途、目标、条件、资源、公开成本；可确定分数与双方冷静值；不确定范围、风险、冒险检定概率及战术说明 |
| 标准 standard | 用途、目标、条件、资源、公开成本；方向与风险；没有 score/selfCalm/opponentCalm/probability 数值预测字段 |
| 硬核 hardcore | 只有用途、目标、必要条件、资源与私证公开成本；整个 forecast 字段不存在 |

模式由服务器房间保存，只有房主能在等待阶段修改；修改清除双方准备状态。新局不可变案件快照保存 matchMode，运行中绑定失配会中止。准备、房间、庭审与重连均读取同一个模式。实际引擎不依据模式分支计分。

硬核隐藏的是当前出招的预测，不是公开规则书、客观证据强度或已生效的资源状态。全部模式结算后均显示真实分数、双方冷静值、消耗、程序原因、局势影响、下一行动方；随机结果也可展开查看。

## 预览权威性与信息边界

`server/preview.ts` 调用 `prepareAction` 做纯计算，先执行同一套合法性验证，再对公开可能性运行规则引擎。全部普通行动、调查／复核、科学家免费技能、六道具、三种普通战术、四种最终陈词均经过该路径。没有第二套复制的计分公式。

证据真实 strength/reliability/flaw/linkedIds、关联表答案、未选择的私人材料不返回前端。对于未知证据证明力及关系，预览计算正／负／零及成立／不成立的保守可能分支，不返回真实隐藏分支。范围可能较宽，这是对隐私的有意约束，**不是该材料的精确预测或胜率**。同一可见状态下，仅修改隐藏权重、缺陷或关联，不会改变预览。

复核与追问的条件分支、随机成功／失败、公示成本、防火墙、分数和冷静值上下限都由同一个引擎计算。公开状态可以确定的反驳、咖啡、总结等提供准确值；道具后续效果另行说明，不把未来条件收益算作本回合即时分数。

预览固定使用模拟骰端点 1／100，绝不调用真实 RNG。只有正式提交才冻结一次真实骰值。客户端修改行动、目标、风格、道具会在约 220ms 后重新请求；过期异步响应不能覆盖新草稿。

## 协议与确认

- `room:create` 新增可选 mode，旧请求默认 standard。
- `room:mode`：仅房主、仅等待阶段。
- `game:preview_action`：ActionDraft（turnId、optionId、evidenceIds、targetArgumentId、itemId、tactic），只私有回执；不广播、不调用 LLM、不改变游戏资源、事件或预算。
- 响应 previewId 为服务器 HMAC，绑定玩家、模式、回合与规范化选择。UI 将它随最终提交发送；选择修改、冒用或过期时拒绝。
- `game:submit_action` 仍为唯一游戏模型调用入口；actionId 幂等检查优先于过期检查。同 ID 同参数重复请求返回原回执，不重掷骰、不重复扣资源。
- 兼容原协议：不带 previewId 的已鉴权显式 submit 仍视为最终确认，服务端重新验证并计算预览；没有另设自动提交路径。新界面必须经过预览和最终弹窗。
- 提交超时重试原 actionId；已接受行动在掉线后只完成一次结算。

新 snapshot experienceVersion=2 在事件中记录 settlement：分数前后、双方冷静值变化、本次资源、局势影响与下一方。历史 experienceVersion=1 不添加这些字段，按原快照复盘。presentation 和 comparison 仅为展示，不参与数值回放校验；分数、资源、双方冷静值及骰值仍严格比较。

新增覆盖：

- 三案八次手动选择的所有合法菜单／风格、私证权限、证据目标变更、战术变更、调查与三身份、六道具；确定值相等，不确定范围包含真实结果。
- 冒险的两个端点、不利证据、评分上限、冷静值上限、防火墙；随机复用、有限重试和预算降级沿用原回归。
- 修改隐藏评分及关联不会改变预览；未知／对方私证被拒绝。
- 三模式同案件／行动／固定骰得到完全一致的实际引擎状态；三模式各通过真实 Socket 连接完成八次预览＋显式提交＋结算＋复盘。
