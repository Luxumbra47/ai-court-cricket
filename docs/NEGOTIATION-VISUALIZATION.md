# 交锋过程可视化

动态谈判桌是现有三幕对局的公开表现层。AI 决策、底线校验、计分、信任和成交规则继续由原有服务端引擎执行；免费模式仍为本地策略代理。

## 界面与操作

- 对局画面只有全屏 3D 第一视角；分栏 3D 与经典 2D 已移除。公开物件与文字实录在左下“桌面档案”抽屉查看。
- 报价卡显示报价者、价格与待接受/已接受状态。旧报价进入历史，有效协议独立保留。
- 声明初始显示“待查证”。查验凭证翻开后持续保留；查验本身不会直接把声明标为反证。
- 质疑将声明与凭证并置、连线，说明具体冲突；服务端确认成立后才显示“已被反证”。不成立时明确显示“质疑未成立”，保留原物件。
- 接受行动形成协议，预览甲方物资与乙方筹码交换。未经接受的新报价不会撤销协议。
- 价格承诺绑定对应报价编号并显示封签。确认违约时展示原承诺、原价格、新报价与裂开的封签。普通公开表态不会自行判定违约。
- 追问仅对传入且验证存在的公开目标高亮；没有目标时只表现询问对方。暂缓不改变桌面。
- **自动演出**：服务端仍在每个回合开始和每次行动后开启门闩；客户端在演出完成并停顿约 800ms 后自动确认，默认无需点击。双方客户端独立确认，服务端仍要求两端都确认，内置陪练自动确认。
- 可随时“暂停演出”，此时停在门闩并显示“继续”；“恢复演出”后继续自动确认。打开“幕后包厢”或“桌面档案”抽屉会暂时暂停，关闭后恢复（主动暂停除外）。
- “1× / 2×”切换动作与朗读速度，“跳过演出”只展示当前这一步的结果并立即停止朗读；未暂停时随后自动确认。
- 全屏顶栏默认开启“代理人语音”：优先由本机服务端用 Windows 已安装的中文语音按正常人类语速合成，浏览器中文语音作兜底；可在顶栏或窗口设置关闭。服务端与浏览器都没有中文语音时按同一阅读时钟无声推进，并显示提示。语音不经过外部服务。
- 点击桌面档案内的时间线查看该次行动结束时的桌面及完整对白。回看本身不会推进对局，也不会触发下一步；提示实时幕次/阶段，返回实时后继续自动演出。
- 完整文字实录保留在“桌面档案”抽屉；赛后关键行动可定位实录。
- 桌面物件在抽屉内部滚动，不覆盖耳语输入；窗口宽度小于 900px、WebGL 不可用或 3D 加载失败时只显示“3D 舞台不可用”提示。
- 同时遵循系统 `prefers-reduced-motion` 与窗口“减少动态效果”。关闭动画时当前这一步直接展开为完整状态，随后按自动演出规则确认。

## 公开事件契约

`shared/whisper.ts` 的 `ActionUnit` 由 `server/engine.ts::applyMove` 产生，挂在同次行动的发言事件 `performance` 上。发言事件编号等于行动编号；执行实录通过 `actionId` 关联，前端只播放一次。

每次行动包括：唯一编号、幕次、分段编号、行动者、原始行动类型、`valid`、`success / failed / noop` 结果、公开发言、客观结果，以及可选的公开目标、报价、声明、凭证、质疑、协议、封签与违约编号。

无效行动保留原提议类型，但标记 `valid=false / failed`，客观结果为“提议未生效”；不产生报价、协议或凭证物件，角色采用暂缓状态。合法但未成立的质疑为 `valid=true / failed`，保留双方引用物件。

`shared/stage.ts` 提供 `actionUnits` 去重和 `rebuildTable` 纯公开事件重建。刷新直接恢复已有物件，不重播历史。按行动编号截断事件即可回看，历史承诺使用当时快照，不能被未来的违约修改。

前端不从自然语言关键词、正则或表情推测结果。演出数据不含底线、对方信任、人格、私密方针、私密备注、计划或私密汇报；公共舞台只使用公开投影。对方性格在对局期间仍为 `null`。底线范围不进入报价可视化。赛后揭密沿用既有规则。

公开卡是公开事件：`promise` 只在存在本方当前报价时绑定价并进入既有承诺账本，`pressure` 在公开低语事件上标记 `publicCard='pressure'` 供本地策略判断，`statement` 只记录文本。公开卡与其 10 字备注双方可见；私密方针与 15 字备注仅留在本方代理人状态和包厢，不进入公开事件、对端数据或 3D。

隐藏副目标不进入公开舞台：服务端 `project` 只在本人 `own.objective` 中投影 `title / description / reward`，对局中不返回 `achieved / detail`；`RoomView` 其他字段、公开 `scenario`、公开事件、公开低语、Socket 对端数据、桌面档案与 3D DOM 均不携带副目标文本。赛后 `Outcome.objectives` 才向双方揭晓标题、说明、达成状态与判定依据，判定只读取公开 `ActionUnit`、承诺账本与最终协议。

## 播放与阶段同步

`src/hooks/useStagePlayback.ts` 每一步依次播放：行动者突出 240ms → 角色行动并朗读整句（由语音实际结束或按正常语速估算上限）→ 物件变化 550ms（翻牌、质疑、协议为 850ms）→ 停在“本步完成”，等待自动确认或手动“继续”。自动确认在门闩就绪后约 800ms 触发；暂停、回看、`drawerOpen` 或未连接时不触发。朗读使用 `src/hooks/useSpeech.ts`，服务端优先调用 Windows 中文语音，浏览器语音兜底；文本清洗与时长估算在 `shared/stage.ts`，约每秒 4.5 个汉字并计入标点停顿。加速时动作与语音同步按倍速缩短；“跳过演出”只展开当前这一步，未暂停时随后自动确认。

每幕交锋和回应分别组成一段，共六段；每幕交锋 3 次行动、回应 1 次，共 12 次 AI 行动。回合开始时服务端先开启开始门闩（`lastActionId=null`）；之后每产生一次行动就开启一次行动门闩，`room.deadline=null`。客户端自动确认，或暂停时由玩家点击后发送：

```text
game:playback-complete { segmentId, lastActionId }
```

开始时 `lastActionId` 为 `null`；行动后为当前行动编号。服务端验证当前分段和行动编号，按认证席位去重。旧分段、错误行动、重复确认均不能推进。`acknowledged` 同时防止自动计时器重复确认。每个门闩默认没有定时自动释放，双方客户端都确认后才继续：开始门闩放行后才进行第一次 AI 决策，行动门闩放行后才进行下一次；因此汇报、信任与文字实录不会跑到玩家前面。一方暂停时停在门闩，另一方确认后显示“等待对方继续”，恢复后继续。内置陪练和掉线席位在门闩创建时视为已完成，断线不会卡住另一方。`playbackWaitMs` 只保留给自动化测试作为显式定时放行。最终结果与赛后揭密也在最后一个行动门闩之后发出。

服务器断线恢复仍使用原有席位认证。重连后页面重新挂载，服务端仍等待当前门闩时按自动演出规则确认，除非玩家暂停；未确认的历史行动在刷新后按已确认桌面重建，不会重复播放。

## 验证入口

```powershell
npm run typecheck
npm test
npm run build
playwright-cli -s=immersive open http://localhost:3010
playwright-cli -s=immersive run-code --filename=scripts/immersive-browser-check.js
playwright-cli -s=immersive run-code --filename=scripts/immersive-unsupported-check.js
playwright-cli -s=scene open http://localhost:3010
playwright-cli -s=scene run-code --filename=scripts/immersive-scene-check.js
```

`immersive-browser-check.js` 通过真实 UI 配置免费代理、创建双人房间，验收全屏 HUD、双席位、方针卡/公开卡、抽屉焦点与遮挡、1280/1440/1920 布局。脚本不再点击门闩：它等待自动演出产生首个行动，暂停后断言门闩停在“继续”且对端显示“等待对方继续”，恢复后断言两页继续前进并在 12 次行动后结束。`immersive-unsupported-check.js` 模拟 WebGL 不可用与 3D 分块加载失败，确认只显示不可用提示而不渲染 2D 舞台。截图写入 `docs/screenshots/`。

`tests/stage.test.ts` 覆盖七类行动、明确目标、真假边界、无效提议、未成立质疑的实际渲染、报价与协议隔离、刷新/回看重建、承诺快照和自动演出门闩的静态渲染（公开谈判桌由 `TableArchive` 渲染）。`tests/server.test.ts` 覆盖双方逐动作确认、旧确认、错误行动、重复确认、无定时放行、断线兜底、陪练豁免、方针/公开卡校验、私密备注隔离、全部六段及最终揭密门闩。

## 3D 全屏沉浸表现层

`src/scene/Stage3D.tsx` 用 Three.js + React Three Fiber 渲染谈判桌。对局舞台只提供全屏 3D：画布固定铺满视口，公开谈判桌、行动时间线、文字实录与右侧常驻包厢改由悬浮 HUD 和抽屉承载。

- 不提供布局模式或布局切换。桌面宽度不小于 900px 且 WebGL 可用时进入 3D；窗口过窄、WebGL 不可用或 3D 模块加载失败时显示“3D 舞台不可用”提示，提供窗口设置与离开入口，不渲染 2D 舞台。
- 全屏顶栏包含品牌、议题、房间码、三幕进度、阶段/倒计时、连接状态、语音与环境音开关、设置和离开；底部固定字幕条与自动演出门闩。`pointer-events` 隔离 HUD，只有画布可拖动转头。1280×720 仍完整显示按钮，页面无外层滚动。
- 三议题按 `room.scenario.id` 切换布景：电池为暴雨窗、应急灯、电池箱与积水；船票为港口雾、船钟、潮汐钟与货箱；档案为档案架、台灯与封存袋。三幕通过 `MOODS` 切换冷宽、暖近与强对比的灯光和曝光。
- 对手只对公开 `ActionUnit` 反应：有效质疑前倾、质疑未成立后仰、查验靠近桌面、成交点头、违约收手、暂缓靠椅背；另有呼吸与眨眼，减少动态效果时关闭。
- 环境音只播放本机 Web Audio 程序化生成的短事件音效：纸张、筹码落下、翻页、质疑、封蜡、盖章、幕间短音与违约裂响。不启动循环底噪、雨声、电流声或持续低频轰鸣；朗读时自动压低，不请求外部音频。结束仪式在成交时把合同与封蜡送入桌中央，未成交则文件收拢、灯光渐熄。
- 左下“桌面档案”抽屉复用 `TableArchive`：报价、协议、声明、凭证、承诺、时间线与完整文字实录。右侧“幕后包厢”抽屉复用 `BackstageBody`：信任、本幕方针、本轮汇报、方针卡/公开卡。耳语阶段未提交时自动打开，提交后自动收起；Esc、遮罩关闭，Tab 焦点约束在抽屉内，抽屉打开时自动演出暂停，遮罩不遮挡底部门闩。
- 每个客户端以 `room.you` 的座位为相机看向 `other(room.you)`；甲看赛芙、乙看维恩。取景上对手位于画面中上部，桌面在下部，己方手臂在手边底缘；16:9 垂直 FOV 约 50°，21:9 约 47°。相机只允许小幅拖动，不自由行走。
- 两名玩家看到同一张桌子的两端。低模角色、光环、桌面物件和暖/冷双色灯光均为程序化生成，不读取私密字段；桌面卡片使用 Canvas 中文纹理，精确文本以桌面档案为准。
- 桌面中部偏上常驻 12 枚筹码盘：这 12 枚是公开“报价刻度”，不是任何一方的预算或余额。另一侧是浅色小托盘，放备用电池、货位或档案盒（标签使用真实物件名，不再使用“标的物”）。公开报价/协议出现后 N 枚筹码移到报价位并排成 1～3 摞，剩余留在盘内；纸签显示“报价 N 枚”或“协议 N 枚”，协议阶段筹码转为旧金。成交时筹码交给卖方、物件交给买方，合同纸与金色封蜡落下；中途协议只显示“待执行”封签，物件不移动。筹码与物件只来自公开 `table.offer / table.agreement`，不读取底线、预算或私密提议。
- `TradeHand`（前臂、手掌与四指，肤色与袖口按席位区分）只在交易动作出现：报价方把 N 枚筹码推上桌并停留约 150～300ms 后收回，卖方报价时轻推物件；换价先由上一报价方把旧筹码收回盘内，再由新报价方摆入；无效报价只做收回手势，不改变公开桌面。首次摆放约 520ms，换价先 250ms 收回再 360ms 摆入，成交交接 850ms，未成交回盘 600ms。动作在 step 2 开始，不新增门闩、不延长自动确认、不增加玩家点击。减少动态效果、回看历史或刷新恢复时不重播手部动作，直接呈现落位、收回或交接的最终状态。
- `.stage-3d` 公开 `data-chips="12"`、`data-lot`（议题 id）、`data-offer`（none 或 `side:price`）、`data-agreement`（none 或价格）、`data-trade`（idle / place / withdraw / handoff / return）。这些属性只来自公开 `table.offer / table.agreement` 与 `room.status / outcome`，不含底线、预算、私密提议或副目标。
- `useStagePlayback` 的 `active / step / table / review / voice.speaking` 直接驱动 3D：step 0 镜头转向行动者，step 1 朗读与手势，step 2 桌面卡片/封签/协议变化，step 3 等待自动确认或暂停后的手动“继续”。语音、服务端门闩与阶段逻辑完全不变，自动确认只在客户端发生。
- 3D 模块通过 `lazy()` 懒加载；减少动态效果关闭呼吸、漂移、尘埃旋转和抽屉转场。
- 全屏只消费公开事件；私密方针、备注、私密汇报、底线、对局秘密与隐藏副目标不进入 3D。

## 实施范围

首版对局舞台使用程序化低模 3D，不引入外部 GLB 或写实角色；性格不参与公开演出的真假判断。游戏规则中仅价格承诺可自动判定履约，其他表态依旧只记录。公开谈判桌与文字实录只存在于“桌面档案”抽屉，准备页与赛后复盘页继续使用原有舞台素材。

房间仍在服务器内存中；服务器重启后需要新开对局。真实付费服务商未用于本次验收。
